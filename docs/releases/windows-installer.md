# Unsigned Windows installer development build

`npm ci`, `uv sync --locked` and `npm run build:installer` build the frontend, freeze the Python engine, compile the release Tauri executable with Cargo.lock enforced and produce an NSIS x64 setup executable. The pinned npm CLI is @tauri-apps/cli 2.12.4. The separate tauri.release.conf.json overlay enables current-user installation; the base development bundle stays disabled. LM Studio remains a separate prerequisite. Missing WebView2 uses Tauri's download-bootstrapper option, so that dependency setup may require network access. See the official Tauri Windows installer guide: https://v2.tauri.app/distribute/windows-installer/.

Outputs are staged in build/installer with sizes and SHA-256 values, alongside a build/native-release directory for restricted-PATH smoke checks. The installer is deliberately unsigned and is a development artifact, not a completed production release. Existing npm audit findings remain recorded separately; no dependency-wide clean-audit claim is made. Signing, notices, version-to-version upgrade acceptance and clean end-user-machine coverage remain unfinished.

Local release boot `.acceptance/5238a416-a464-4f85-8298-3360c7f6e1b3/` passed with PATH limited to Windows System32 and Python/virtualenv paths removed. The real release desktop starts its adjacent frozen engine, authenticates API requests, creates no runs, requests no inference and closes with a graceful engine shutdown. This proves standalone release startup on the development machine; it does not prove installation/uninstallation or clean-machine prerequisites. The first completed local installer is approximately 22.13 MiB. The current manifest is regenerated for each build; hashes are artifact-specific rather than a reproducible-byte guarantee.

The Windows installer CI job runs after source checks on main, installs the pinned Rust toolchain, builds the package and uploads an unsigned installer/manifest artifact for 14 days. `scripts/installer_ci_smoke.ps1` is restricted to a disposable GitHub Actions runner, refuses an existing test destination, installs under RUNNER_TEMP, checks both binaries, runs the installed app under restricted PATH, then uninstalls and checks that binaries were removed and a default-data-directory marker was preserved. This is the first install/uninstall test, pending hosted execution. It does not claim upgrade or optional user-data-removal coverage. The native boot script never downloads a model or requests inference.

First hosted package run 41790142305 built the installer successfully but failed its installed WebView readiness check. The saved install-smoke report confirms uninstaller exit 0, removal of installed binaries and preservation of the data marker; overall passed is false because boot was not verified. The initial test lacked startup diagnostics and allowed about 20 seconds for a cold WebView. The retry records bounded desktop stdout/stderr and engine-startup logs, gives cold startup a bounded 60-second allowance and still requires actual DOM/API readiness, authenticated access and graceful shutdown. This is not yet a proven fix for the hosted failure. Hidden acceptance reports are explicitly included in CI artifacts, and successful compilation caches are saved even if a later smoke check fails.

Packaging now derives the installer filename/version from tauri.conf.json and requires the installer modification time to belong to the current build, preventing a stale older setup file from being staged. The CI installation script selects the manifest's filename and verifies both installer and installed desktop/engine SHA-256 values. The version-derived local rebuild succeeds; a new local release boot passes in 1645 ms in .acceptance/e57438f7-1921-41c1-aacd-7109be7166f5/. Hosted retry remains pending.
