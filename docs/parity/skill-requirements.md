X.A.A. discovery follow-up: the desktop now offers an explicit lexical suggestion action over active procedure name/description/category metadata, requires a clear multi-term or exact-name match, reports matched terms, and filters candidate/evaluated-only entries. The user inspects the active version and separately chooses it for a run; no instructions are loaded or selected automatically. This remains metadata-based assistance rather than semantic retrieval or full Hermes discovery parity. Details and verification are recorded in [`procedure-candidates.md`](../architecture/procedure-candidates.md).

Pinned package compatibility follow-up (2026-11-06): the exact pin contains 44 default bundled and 142 optional skills across 1,127 tracked files. X.A.A. accepts the Hermes-specific nested `metadata.hermes` extension without treating it as authority and resolves its category with conflict checks. The procedure body limit is 80 KiB, enough for all 186 pinned `SKILL.md` files (largest 72,164 bytes); frontmatter discovery still reads a 16 KiB prefix. Selected runs retrieve the immutable body through `procedure_view` on demand. Standalone Hermes skill directories can be discovered from a catalog root or directly and imported as inactive candidates with bounded linked text resources; the source digest is retained, and no `plugin.json` wrapper is required. The reproducible pinned importer audit passes 186/186 source directories, including linked text-resource resolution; dependency setup, behavioral parity, declaration execution and scripts remain open. Hermes `requires_toolsets`, `requires_tools`, `fallback_for_toolsets` and `fallback_for_tools` filter model-visible catalog results against the current run tool schema, and declared `platforms` hide incompatible entries from that catalog; declarations remain untrusted and grant no tools or permissions. Command and environment readiness is advisory only; imported script execution remains unsupported. See [`skill-package-inventory.md`](skill-package-inventory.md). This is package-source coverage and compatibility fixes, not complete skill parity.

The reference's bundled/optional synchronization and external hub/catalog package paths still need deeper lifecycle and dependency audits. No claim is made that a procedure editor, three tool schemas or a static package manifest establishes full Hermes skills parity. Existing X.A.A. model tools cannot invoke the user-only evaluation or lifecycle APIs.
