# Pinned skill package inventory

Reference: Hermes commit `1e208b280deb18f01d015b0acdf3ef3552d08039`, audited 2026-11-06. The generated [`skill-package-inventory.json`](skill-package-inventory.json) fingerprints tracked files under `skills/` and `optional-skills/`, parses bounded YAML frontmatter, records package-relative files and local Markdown destinations, and does not import or execute package content.

Regenerate or check from the repository root with:

```powershell
uv run python scripts/audit_skill_packages.py
uv run python scripts/audit_skill_packages.py --check
```

The inventory script requires the clean pinned `.hermes-audit` checkout used by the other source audits. It fetches blob contents in one Git batch and stores hashes, modes, and bounded metadata rather than skill bodies. To exercise the X.A.A. importer against every recorded standalone source directory, run `uv run python scripts/audit_skill_import_compatibility.py --check`.

## Inventory findings

- The pin contains 44 default bundled skills and 142 optional skills in 23 categories, covering 1,127 tracked files. Optional skills are shipped but not active by default. Thirty-six files have the executable Git mode; many more package files are scripts or code examples without that mode.
- All 186 skills declare `platforms`; 148 include Windows, 182 Linux, and 184 macOS. All declare `name`, `description`, `version`, `author`, and `license`. Twenty-five use `prerequisites`, 30 use `dependencies`, and 181 use the Hermes-specific nested `metadata.hermes` extension. The 30 pinned `dependencies` declarations are lists, including version-constrained package names; they do not identify a dependency manager. Ten packages contain a `requires_toolsets` key, with nine non-empty declarations (using `terminal`, `files`, or `kanban`) and one empty list. No pinned package declares `requires_tools`, `fallback_for_toolsets`, or `fallback_for_tools`. Hermes documents these as conditional skill visibility fields; X.A.A. preserves and displays them as untrusted declarations but does not automatically hide, select, or authorize procedures from them. None declares Agent Skills `allowed-tools` at top level. Package dependency, credential, and tool requirements therefore cannot be inferred from a tool manifest alone.
- X.A.A. now accepts the pinned `metadata.hermes` mapping as untrusted package metadata and uses its `category` only when the standard `metadata.category` is absent. Conflicting categories are rejected. Discovery shows a bounded summary of declared platforms, Hermes conditional `requires_toolsets`/`requires_tools` and fallback fields, prerequisite field and executable names, required environment-variable names, dependency counts, and validated dependency package names. Manager names are shown only when the package declares a mapping; package lists such as the pinned Hermes format do not imply a manager. Version constraints, direct URLs and unparsed dependency values are omitted. A per-discovery check compares platform declarations, command-name presence on `PATH`, and required environment-name presence with the current engine process. At most 256 distinct command names are checked in one scan; further names are explicitly reported as unchecked. The check reveals neither environment values nor command paths and is not persisted. The declaration summary is retained in immutable candidate source provenance. This check does not establish command semantics, package installation, Hermes conditional-visibility compatibility, execution readiness, or permissions. The original bounded skill text, including its frontmatter, remains part of the inactive candidate.
- The candidate text bound is now 80 KiB, which covers all 186 pinned `SKILL.md` files (largest: 72,164 bytes). The discovery scanner still reads only a 16 KiB prefix for frontmatter. Full procedure text is loaded only through the selected-run `procedure_view` tool. The reproducible bounded importer audit passes for all 186 source directories, including linked text-resource resolution. It tests import parsing and resource limits only; it does not establish dependency readiness, declaration semantics, script execution or behavioral parity.
- Supporting scripts and non-text resources remain inert. X.A.A. does not run imported scripts, and its linked-resource reader accepts bounded UTF-8 text only. The current-machine declaration check is advisory and grants no permissions; dependency installation, toolset support and full execution readiness remain unresolved.

The package metadata regression tests pass with nested Hermes tags, related-skill lists, category fallback, and conflict refusal. Direct standalone-directory discovery/import tests pass, and the pinned importer audit passes 186/186. This does not establish full Hermes skill parity, automatic installation, dependency setup, toolset/permission mapping, behavioral acceptance or safe script execution. External catalog skills and the broader package/hub lifecycle remain separate audits.
