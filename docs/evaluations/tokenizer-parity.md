# LM Studio tokenizer parity probe

Measured 2026-11-04 with optional Python SDK `lmstudio==1.5.0`, the installed `qwen/qwen3.5-9b` model and a 16,384-token loaded context. The original 1.5.0 measurement used a temporary development dependency. The subsequent engine counting service pins and bundles 1.6.0b1 for its API-token support; see the service notes below. No models were downloaded. The exact HTTP-loaded instance was selected through the SDK's loaded inventory.

| Fixture | SDK formatted prompt tokens | HTTP reported prompt tokens |
|---|---:|---:|
| Plain user text | 13 | 13 |
| Tool definitions | 280 | 280 |
| Assistant tool call and tool result | 324 | 324 |
| System/chat history with Unicode | 40 | 40 |

All four matched. Evidence: `.acceptance/20de837c-6997-4b71-911e-295aa7bd1bfd/report.json`. Reproduce with `uv run --with lmstudio==1.5.0 python scripts/tokenizer_parity_diagnostic.py`. Each HTTP comparison limits output to one token; only fixture content is used. The tool-result history is explicitly seeded and no agent tool is executed. Model inference is real, and the model is unloaded afterward. Reports save counts and context size rather than rendered prompts or private reasoning.

The SDK accepts tool definitions in prompt-template options. For tool history, its public Chat builder requires tool-call parts wrapped as `toolCallRequest`; plain wire dictionaries passed to Chat.from_history or unwrapped requests passed to add_assistant_response were rejected. Earlier partial probes `.acceptance/9c760eeb-5061-4fda-b533-fc6c459e4b8d/` and `.acceptance/0fbfa182-7741-4399-88b9-700448d4fdea/` retain those conversion failures after matching the first two fixtures. The corrected probe uses the public builders and validates all four fixtures.

This is evidence for one model and fixture set, not a general compatibility or hard-budget claim. Weight/quantization files and server release were not fingerprinted. Other models, prompt-template overrides, multimodal inputs, tool schema variants, parallel calls and reasoning-history conventions remain unevaluated. Authentication handoff, owned-process cancellation/timeouts and packaging now have service-level evidence linked below. Automatic serialized count/reserve/infer ownership, atomic durable reservations and broader compatibility checks still need implementation before hard budgets can rely on this path.

Official reference checked 2026-11-04: [LM Studio Python tokenization](https://lmstudio.ai/docs/python/tokenization) documents formatting the chat, tokenizing it and checking loaded context. SDK 1.5.0's installed typed interfaces and public Chat methods were also inspected to determine tool-definition/history conversion.

Engine integration follow-up: SDK 1.6.0b1 direct parity passed in `.acceptance/afe13138-518d-4195-b32b-78f4d8fd3203/`; owned engine-worker parity passed in `.acceptance/79d8eeb0-cd3d-4455-a383-ddb333fd6670/`, with the same four counts. `uv run python scripts/tokenizer_parity_diagnostic.py --engine` exercises that worker. [Service design and scope](../architecture/tokenizer-service.md) documents authentication, cancellation, packaging and remaining limits. Core inference has not switched to automatic exact counting.

Full-catalog follow-up (2026-11-04): the real plan tool exposed an SDK schema incompatibility beyond the earlier four fixtures. SDK 1.6.0b1 retains nested `$ref` but drops root `$defs`; the formatter then rejects the unresolved reference. `providers/tool_schemas.py` expands bounded acyclic in-document references for both HTTP inference and SDK counting, preserves constraints and literal default/example data, and rejects unsupported scoped/external/cyclic references. Original application argument validation remains authoritative. The failed run is retained at `.acceptance/9c8bf7ac-13ca-45ef-9000-2b9d2593acf2/`.

`scripts/canonical_context_diagnostic.py` now counts each actual request in a real source coordinator read run, including the complete plan/file/Git tool catalog and returned file result. Successful evidence `.acceptance/78c560b5-c420-4ae5-932b-8e39b0b5a0b9/` matches SDK/HTTP prompt counts 314, 148, 1469 and 1639 on `qwen/qwen3.5-9b` with context 32768. Raw responses included the field name `reasoning_content`; no private field values were captured in the report, and newly persisted assistant messages contain only public fields. The file nonce was read correctly without fixture modification. This is one model/run, instrumented count-then-infer, not an atomic reservation or automatic runtime admission policy.

Automatic SDK context admission (2026-11-04): set `XAA_EXACT_CONTEXT=1` before launching the engine/desktop to enable the opt-in path. The provider holds its existing inference/lifecycle lock continuously across fixed-worker counting and the subsequent normal or streamed HTTP request. It checks SDK prompt tokens plus the selected output cap against the live loaded context. If no cap is supplied, this mode supplies and verifies a 512-token cap. Counting/validation failure or a mismatched model identifier prevents inference; there is no silent estimate fallback or history truncation. Counting is bounded to five seconds once the provider owns the queue. Already-loaded exact instance IDs and current loopback SDK compatibility are required. The default mode retains conservative admission while broader model/template parity is evaluated.

Unit checks cover normal/streamed ownership, lifecycle exclusion, equality at the context boundary, counting failure and cancellation without prediction. Real automatic source-run evidence `.acceptance/5c9c139f-4541-4573-afd0-3902efc193ea/` matches four actual counts (312, 142, 1469, 1636), reads the nonce correctly and preserves fixture bytes/mtime. `scripts/exact_context_diagnostic.py` evidence `.acceptance/71ec5fc2-f1bb-48a8-832b-3529e40145bf/` rejects normal and streamed prompt-plus-16384-output requests before HTTP on context 16384; one admitted streamed request matches SDK/HTTP prompt count 15 and finishes normally. Earlier `.acceptance/65a0e676-fb00-48ab-b047-41b2b3e3cc8a/` is retained: its 64-token streamed output ended without a public answer; the passing trial uses 512. This remains one installed 9B model, no durable run-tree token reservation, and no protection against independent LM Studio clients changing server state outside this provider's lock.

Consecutive-message follow-up: real procedure trial exposed the SDK builder merging consecutive user messages, unlike the HTTP request. Conversion now uses one builder per message and public typed-history construction to retain message boundaries. `.acceptance/51cecc55-37e3-4190-81a4-f26aa18700b9/` matches all four real trial counts; `.acceptance/1fa71d2c-b186-4ad5-9157-34313c2b78a8/` retains standard 13/280/324/40 fixture parity. Earlier failed trial `.acceptance/03a10f2f-fccc-42eb-afb5-8df6404e9f4d/` remains evidence of the compatibility gap.
