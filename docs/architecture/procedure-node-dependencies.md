# Procedure Node.js dependencies

## Current support

X.A.A. stages linked `.js`, `.mjs`, and `.cjs` resources into restricted WSL command snapshots and reports the selected WSL Node/npm versions. The authenticated desktop inspects linked `package-lock.json` v3 and `package.json` resources against the exact imported procedure and a fresh WSL runtime check. A network-denied Windows AppContainer worker parses the manifest and lock, validates their agreement, checks package names/paths, registry URLs, SHA-512 integrity, root and transitive edges, and strict npm SemVer ranges, requires non-optional dependencies to resolve, validates optional and peer dependencies, and rejects unreachable lock records. The parent verifies the exact asset hashes and strictly validates the worker's returned lock both during inspection and again before saving. For a saved pending proposal, a separate network-denied Windows AppContainer worker fetches only exact locked tarball URLs through a fixed-host `registry.npmjs.org` broker, with redirects disabled and count, per-archive, aggregate-byte, protocol, and time limits. The acquisition worker verifies archive integrity, identity, paths, and lifecycle metadata; the parent independently verifies each returned archive. Exact proposals and verified tarballs are stored under the lock digest, and the desktop shows every package, byte size, integrity, and lifecycle script before owner approval.

The graph inspection depends on `node-semver==0.9.1`, pinned with wheel and source hashes in `uv.lock`; strict mode excludes prereleases unless a range admits them. The parser accepts at most 512 package records and 20,000 dependency edges, with a 64 KiB worker request, 6 MiB result, 30-second execution deadline, and private input snapshot. The acquisition path caps each compressed archive at 64 MiB, the aggregate download at 256 MiB, and the worker at 120 seconds. Archive verification caps decompressed stream bytes at 320 MiB, members at 20,000, each file at 64 MiB, and declared expansion at 256 MiB; verification writes or executes no package contents. Approved locks can be installed offline into an immutable managed WSL tree and bound to exact procedure runs as described in step 5. See [npm SemVer ranges](https://github.com/npm/node-semver#ranges) and the [npm SemVer package](https://github.com/podhmo/python-node-semver).

## Environment identity

A Node environment should be identified by the imported procedure ID/version and source hash, the exact `package.json` and lockfile hashes, target WSL distribution, Node/npm versions, normalized declared requirements, and every package path/version/tarball digest. Any change creates a separate environment digest; installed trees stay immutable and are removed by exact digest only.

The current parser accepts lockfile format version 3, registry tarballs on `https://registry.npmjs.org`, and SHA-512 SRI values. It refuses links, bundled packages, alternate registries, URL/Git dependency declarations, and other lockfile formats. These are validation boundaries for the first implementation slice, not a claim that every npm project can be installed.

## Lifecycle status and remaining acceptance

1. Read `package.json` and `package-lock.json` only from integrity-checked linked resources of the selected imported procedure version. Require exact manifest/lock consistency and verify supported root and transitive dependency ranges and graph closure with the pinned semantic-version implementation. This inspection now runs in the network-denied AppContainer worker; broader npm install semantics remain subject to acceptance before claiming general compatibility.
2. Resolve only supported public registry records. Exact tarball URL requests and archive metadata parsing run in the isolated, network-denied AppContainer worker behind the fixed-host broker; redirects are disabled and byte, count, size, time, and protocol limits apply. Package lock graph parsing also runs in the AppContainer worker. Worker and parent verify every tarball SRI digest and package identity.
3. Persist the exact proposal and acquired tarballs under a content-addressed identity. The desktop displays the complete package set, versions, acquired byte sizes, integrity values, and lifecycle-script presence, and requires separate owner approval for that digest. This step is implemented; broader UX acceptance remains in progress.
4. Install only the approved lock into a new, unprivileged, network-denied WSL environment. **Implemented for the first install slice:** the trusted root manager rechecks the exact lock/resource hashes and every tarball's SHA-512 integrity, then copies them into private staging. It preloads the exact local tarballs with `npm cache add --offline --ignore-scripts` and runs fixed `npm ci --offline --ignore-scripts --no-audit --no-fund`; package scripts are not invoked. The process runs as uid/gid 65534 inside Bubblewrap with no network namespace, a 1 GiB memory limit, 50% CPU, 64 tasks, and a 240-second systemd runtime. Aggregate expanded tarball size is capped at 1 GiB; the installed tree is capped at 1.5 GiB and 50,000 files. Only safe relative in-tree npm bin symlinks are accepted; the tree is hashed, made root-owned and read-only, and its manifest is published after completion. The authenticated API persists the verified receipt and the desktop offers install/remove actions. Live WSL acceptance verifies offline module loading, a generated `.bin` symlink, lifecycle marker absence, repeat install, integrity status, and exact removal. A second live acceptance installs a scoped package with a nested transitive dependency from exact locked tarballs, then imports it inside a procedure-bound command: [report](../../.acceptance/npm-transitive-graph-20261114/report.json). These are deterministic fixture graphs on Ubuntu 24.04; broad npm package compatibility remains unverified. Procedure execution binding is verified in step 5.
5. **Implemented and locally verified:** a run may select only an approved installed lock for the exact imported procedure version and authorized WSL distribution. A unique installed match is recorded automatically; multiple matches require an explicit digest choice. The immutable selection event stores the environment digest, distribution, and tree hash. The command journal binds this proof and the procedure ID/version to the command intent. WSL rechecks the installed tree under a shared lease, mounts only its node_modules read-only for that procedure version, and adds its .bin directory to the sandbox PATH. The lease remains held through manager cleanup, so removal is refused until the command finishes. Live WSL acceptance imports a fixture from the selected procedure script, observes removal refusal during an active command, verifies cleanup, then removes the exact environment: [report](../../.acceptance/npm-node-environment-6b7f7990aeaf4a5fabbe17763ede3bac/report.json). A second acceptance runs two distinct procedure IDs concurrently with the same package name/version but different verified archive bytes; each imports its own module value, active removal is refused for both, and exact cleanup preserves the other environment: [report](../../.acceptance/npm-cross-procedure-isolation-20261114/report.json). These are deterministic fixtures on one WSL distribution and do not establish model-mediated procedure execution or broad npm compatibility.
6. **Partially verified lifecycle/recovery:** exact-digest removal can recover an invalid manifest or corrupt tree while holding the manager lock and exclusive digest lease; it verifies the exact root-owned directory, stops the exact transient installer unit, and confirms it is inactive before deletion. Unit regressions cover corrupt-manifest removal, adjacent-environment preservation, and refusal while a command holds the lease. Live WSL acceptance kills a real offline npm installer service with SIGKILL, verifies no partial receipt remains, and retries the same digest: [process-kill report](../../.acceptance/npm-process-kill-recovery-20261114/report.json). It installs procedure version 2 under a separate digest, runs the retained version 1 successfully, removes v2, confirms v1 remains intact, then removes v1: [rollback/runtime/isolation report](../../.acceptance/npm-version-rollback-20261114/report.json). The same acceptance confirms the module link resolves only through the selected procedure path, no project-root `node_modules` appears, and hashes of the WSL Node/npm trees and global-module location are unchanged across install, execution, and removal. These checks cover one WSL distribution and deterministic fixtures. Source and frozen Windows AppContainer workers reject correctly integrity-hashed tarballs with traversal, absolute/backslash paths, symbolic and hard links, FIFO entries, duplicate members, missing package metadata, truncated or checksum-invalid gzip streams, per-file size over 64 MiB, more than 20,000 members, and aggregate expansion above 256 MiB: [30-case worker matrix](../../.acceptance/npm-archive-bounds-20261114/report.xml). This does not establish broad npm archive or package compatibility. The model-mediated imported procedure run remains deferred until the end per the user's preference.

npm's package lock and `npm ci` semantics are documented at [package-lock.json](https://docs.npmjs.com/files/package-lock.json) and [npm ci](https://docs.npmjs.com/cli/commands/npm-ci/). In particular, `npm ci` requires a lockfile and checks that the lock and manifest agree; `ignore-scripts` prevents install-time lifecycle scripts but does not prohibit deliberately invoking a script command. X.A.A. must keep installation commands fixed and execute no package script as part of setup.
