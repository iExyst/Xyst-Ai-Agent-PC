# Procedure Node.js dependencies

## Current support

X.A.A. stages linked `.js`, `.mjs`, and `.cjs` resources into restricted WSL command snapshots and reports the selected WSL Node/npm versions. The authenticated desktop inspects linked `package-lock.json` v3 and `package.json` resources against the exact imported procedure and a fresh WSL runtime check. A network-denied Windows AppContainer worker parses the manifest and lock, validates their agreement, checks package names/paths, registry URLs, SHA-512 integrity, root and transitive edges, and strict npm SemVer ranges, requires non-optional dependencies to resolve, validates optional and peer dependencies, and rejects unreachable lock records. The parent verifies the exact asset hashes and strictly validates the worker's returned lock both during inspection and again before saving. For a saved pending proposal, a separate network-denied Windows AppContainer worker fetches only exact locked tarball URLs through a fixed-host `registry.npmjs.org` broker, with redirects disabled and count, per-archive, aggregate-byte, protocol, and time limits. The acquisition worker verifies archive integrity, identity, paths, and lifecycle metadata; the parent independently verifies each returned archive. Exact proposals and verified tarballs are stored under the lock digest, and the desktop shows every package, byte size, integrity, and lifecycle script before owner approval.

The graph inspection depends on `node-semver==0.9.1`, pinned with wheel and source hashes in `uv.lock`; strict mode excludes prereleases unless a range admits them. The parser accepts at most 512 package records and 20,000 dependency edges, with a 64 KiB worker request, 6 MiB result, 30-second execution deadline, and private input snapshot. The acquisition path caps each compressed archive at 64 MiB, the aggregate download at 256 MiB, and the worker at 120 seconds. Archive verification caps decompressed stream bytes at 320 MiB, members at 20,000, each file at 64 MiB, and declared expansion at 256 MiB; verification writes or executes no package contents. Approved locks can now be installed offline into an immutable managed WSL tree, but that tree is not yet bound to procedure command execution. See [npm SemVer ranges](https://github.com/npm/node-semver#ranges) and the [npm SemVer package](https://github.com/podhmo/python-node-semver).

## Planned immutable identity

A Node environment should be identified by the imported procedure ID/version and source hash, the exact `package.json` and lockfile hashes, target WSL distribution, Node/npm versions, normalized declared requirements, and every package path/version/tarball digest. Any change creates a separate environment digest; installed trees stay immutable and are removed by exact digest only.

The current parser accepts lockfile format version 3, registry tarballs on `https://registry.npmjs.org`, and SHA-512 SRI values. It refuses links, bundled packages, alternate registries, URL/Git dependency declarations, and other lockfile formats. These are validation boundaries for the first implementation slice, not a claim that every npm project can be installed.

## Required lifecycle before execution support

1. Read `package.json` and `package-lock.json` only from integrity-checked linked resources of the selected imported procedure version. Require exact manifest/lock consistency and verify supported root and transitive dependency ranges and graph closure with the pinned semantic-version implementation. This inspection now runs in the network-denied AppContainer worker; broader npm install semantics remain subject to acceptance before installation support.
2. Resolve only supported public registry records. Exact tarball URL requests and archive metadata parsing run in the isolated, network-denied AppContainer worker behind the fixed-host broker; redirects are disabled and byte, count, size, time, and protocol limits apply. Package lock graph parsing also runs in the AppContainer worker. Worker and parent verify every tarball SRI digest and package identity.
3. Persist the exact proposal and acquired tarballs under a content-addressed identity. The desktop displays the complete package set, versions, acquired byte sizes, integrity values, and lifecycle-script presence, and requires separate owner approval for that digest. This step is implemented; broader UX acceptance remains in progress.
4. Install only the approved lock into a new, unprivileged, network-denied WSL environment. **Implemented for the first install slice:** the trusted root manager rechecks the exact lock/resource hashes and every tarball's SHA-512 integrity, then copies them into private staging. It preloads the exact local tarballs with `npm cache add --offline --ignore-scripts` and runs fixed `npm ci --offline --ignore-scripts --no-audit --no-fund`; package scripts are not invoked. The process runs as uid/gid 65534 inside Bubblewrap with no network namespace, a 1 GiB memory limit, 50% CPU, 64 tasks, and a 240-second systemd runtime. Aggregate expanded tarball size is capped at 1 GiB; the installed tree is capped at 1.5 GiB and 50,000 files. Only safe relative in-tree npm bin symlinks are accepted; the tree is hashed, made root-owned and read-only, and its manifest is published after completion. The authenticated API persists the verified receipt and the desktop offers install/remove actions. A local WSL fixture verifies offline module loading, a generated `.bin` symlink, lifecycle marker absence, repeat install, integrity status, and exact removal. It does not establish procedure execution binding.
5. **Still required:** bind a selected installed environment digest and tree hash into an immutable procedure-selection event. Mount only that environment read-only for commands authorized to run that exact procedure version. Hold an active-use lease through cleanup and refuse removal while in use.
6. Accept interrupted-install recovery, idempotent reinstall, rollback to an older digest, removal, system/runtime preservation, project isolation, and hostile package path/tarball cases before claiming support. The model-mediated imported procedure run remains deferred until the end per the user's preference.

npm's package lock and `npm ci` semantics are documented at [package-lock.json](https://docs.npmjs.com/files/package-lock.json) and [npm ci](https://docs.npmjs.com/cli/commands/npm-ci/). In particular, `npm ci` requires a lockfile and checks that the lock and manifest agree; `ignore-scripts` prevents install-time lifecycle scripts but does not prohibit deliberately invoking a script command. X.A.A. must keep installation commands fixed and execute no package script as part of setup.
