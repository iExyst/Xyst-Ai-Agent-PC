# Procedure Node.js dependencies

## Current support

An optional linked `.npmrc` is limited to boolean `legacy-peer-deps` and `install-links` settings, bound by SHA-256 in the reviewed lock, and rechecked before installation; registry, authentication, and all other settings are rejected. The offline installer passes both reviewed values explicitly to `npm ci`, and lock graph validation omits peer edges when legacy peer resolution is enabled. Unit, API/storage/worker, browser, type, contract, and desktop build checks pass. Ubuntu 24.04 WSL acceptance also passes with both non-default reviewed options, without registry access, and verifies lifecycle suppression, procedure execution, recovery, isolation, runtime integrity, and cleanup ([local report](../../.acceptance/npmrc-install-options-20261124/report.json); [hosted run](https://github.com/iExyst/Xyst-Ai-Agent-PC/actions/runs/45439288908)). The formatted-source workflow [45439970886](https://github.com/iExyst/Xyst-Ai-Agent-PC/actions/runs/45439970886) passed with 1,694 tests passed and 29 skipped. Exact-commit installer workflow [45440717102](https://github.com/iExyst/Xyst-Ai-Agent-PC/actions/runs/45440717102) passed all 58 steps, including installed execution, upgrade, native recovery, standard-user installation, uninstall, and explicit data removal; its reports and manifest are under [`.acceptance/hosted-installer-45440717102/`](../../.acceptance/hosted-installer-45440717102/). This package acceptance verifies the baseline installer, not the specific `.npmrc` options through the installed app.

The installed-package diagnostic invokes the exact installed engine to confirm both supported `.npmrc` options in the isolated lock result and reject registry overrides. Local source/frozen AppContainer coverage passes; hosted installer verification for this diagnostic is pending.

X.A.A. stages linked `.js`, `.mjs`, and `.cjs` resources into restricted WSL command snapshots and reports the selected WSL Node/npm versions and Node architecture. The authenticated desktop inspects linked `package-lock.json` v1/v2/v3 and `package.json` resources against the exact imported procedure and a fresh WSL runtime check. A network-denied Windows AppContainer worker parses the manifest and lock, validates their agreement, checks package names/paths, registry URLs, SHA-512 integrity, root and transitive edges, and strict npm SemVer ranges, requires non-optional dependencies to resolve, validates optional and peer dependencies where represented by the lock format, and rejects unreachable lock records. The isolated parser checks an authored root `packageManager` declaration against the fixed npm installer and exact selected npm version; other package managers and malformed or mismatched versions are rejected during review and rechecked before installation. It validates root `engines.node` and `engines.npm` syntax and records incompatible ranges as advisory warnings, matching npm's default `engine-strict=false` behavior. The fixed offline installer explicitly sets `--engine-strict=false` so ambient npm configuration cannot turn those advisory ranges into install failures. It applies root `devEngines` checks for runtime, package manager, OS, CPU, and libc, including npm's alternative candidates and fatal versus non-fatal `onFail` outcomes. Non-fatal warning-mode mismatches are included in the reviewed lock and displayed in the dependency review even when the selected npm version does not surface them; ignored mismatches remain quiet. It also rejects malformed root `os` metadata, procedures whose declared platform excludes Linux, and malformed or incompatible root `cpu` and `libc` metadata against the selected WSL Node architecture and detected libc family. The fixed offline installer rechecks the reviewed Node architecture, libc family, and Node/npm versions. The parent verifies exact asset hashes and strictly validates the worker's returned lock during inspection and again before saving. For a saved pending proposal, a separate network-denied Windows AppContainer worker fetches only exact locked tarball URLs through a fixed-host `registry.npmjs.org` broker, with redirects disabled and count, per-archive, aggregate-byte, protocol, and time limits. The acquisition worker verifies archive integrity, identity, paths, and lifecycle metadata; the parent independently verifies each returned archive. Exact proposals and verified tarballs are stored under the lock digest, and the desktop shows every package, byte size, integrity, and lifecycle script before owner approval.

The graph inspection depends on `node-semver==0.9.1`, pinned with wheel and source hashes in `uv.lock`; strict mode excludes prereleases unless a range admits them. The parser accepts at most 512 package records and 20,000 dependency edges, with a 64 KiB worker request, 6 MiB result, 30-second execution deadline, and private input snapshot. The acquisition path caps each compressed archive at 64 MiB, the aggregate download at 256 MiB, and the worker at 120 seconds. Archive verification caps decompressed stream bytes at 320 MiB, members at 20,000, each file at 64 MiB, and declared expansion at 256 MiB; verification writes or executes no package contents. Approved locks can be installed offline into an immutable managed WSL tree and bound to exact procedure runs as described in step 5. See [npm SemVer ranges](https://github.com/npm/node-semver#ranges) and the [npm SemVer package](https://github.com/podhmo/python-node-semver).

## Environment identity

A Node environment should be identified by the imported procedure ID/version and source hash, the exact `package.json` and lockfile hashes, target WSL distribution, Node/npm versions, normalized declared requirements, and every package path/version/tarball digest. Any change creates a separate environment digest; installed trees stay immutable and are removed by exact digest only.

The parser and trusted installer accept lockfile formats v1, v2, and v3. For v1, the parser derives root dependency declarations from the exact linked `package.json` and converts the nested dependency tree into package paths; the trusted WSL installer independently checks every package path and identity against the approved proposal. For v2/v3, the canonical `packages` map is used. Supported registry tarballs must use `https://registry.npmjs.org` and provide SHA-512 SRI values. Authenticated v1 and v2 owner flows passed with real `is-odd@3.0.1` → `is-number@6.0.0` graphs, offline WSL installation, procedure-bound import, and exact removal ([v1](../../.acceptance/npm-lock-v1-owner-flow-20261114-final/report.json); [v2](../../.acceptance/npm-lock-v2-owner-flow-20261114-retry1/report.json)). The implementation refuses linked or bundled packages, alternate registries, URL/Git dependency declarations, and unknown lockfile formats. These are validation boundaries for the current implementation, not a claim that every npm project can be installed.

## Lifecycle status and remaining acceptance

1. Read `package.json` and `package-lock.json` only from integrity-checked linked resources of the selected imported procedure version. Require exact manifest/lock consistency and verify supported root and transitive dependency ranges and graph closure with the pinned semantic-version implementation. Check an authored `packageManager` declaration, root Node/npm engine syntax, root `os`/`cpu`/`libc` constraints, and `devEngines` declarations against the selected WSL runtime before approval. Incompatible root Node/npm engine ranges are retained as advisory warnings under npm's default `engine-strict=false`; malformed ranges fail review. Warning-mode `devEngines` mismatches are retained in the lock and shown in the desktop review. This inspection runs in the network-denied AppContainer worker. These metadata checks have focused unit, API, source/frozen AppContainer and browser coverage. Exact installer acceptance [45410237588](https://github.com/iExyst/Xyst-Ai-Agent-PC/actions/runs/45410237588) passed for the warning-display package and standard-user lifecycle. Exact-source CI [45412350686](https://github.com/iExyst/Xyst-Ai-Agent-PC/actions/runs/45412350686) passed 1,674 tests with 26 skipped, including the lock-serialization regression. Broader npm install semantics remain unverified and are not claimed as general compatibility.
2. Resolve only supported public registry records. Exact tarball URL requests and archive metadata parsing run in the isolated, network-denied AppContainer worker behind the fixed-host broker; redirects are disabled and byte, count, size, time, and protocol limits apply. Package lock graph parsing also runs in the AppContainer worker. Worker and parent verify every tarball SRI digest and package identity. A live acceptance fetched pinned `is-odd@3.0.1` and its `is-number@6.0.0` dependency through this path, then installed both offline and imported the root package from the bound procedure command: [report](../../.acceptance/npm-live-registry-transitive-20261114/report.json). This exercises one small two-package graph, not general package compatibility.
3. Persist the exact proposal and acquired tarballs under a content-addressed identity. The desktop displays the complete package set, versions, acquired byte sizes, integrity values, and lifecycle-script presence, and requires separate owner approval for that digest. The live API acceptance imports linked package resources, persists the exact inspected lock, rejects approval before acquisition, rejects installation before approval, acquires the real archive set, then records explicit approval: [owner-flow report](../../.acceptance/npm-live-registry-api-20261114/success/report.json). The `skills.spec.ts` Playwright flow also covers the rendered panel and mocked API transitions (1 passed locally); it is not a live browser-to-API acceptance.
4. Install only the approved lock into a new, unprivileged, network-denied WSL environment. **Implemented for the first install slice:** the trusted root manager rechecks the exact lock/resource hashes and every tarball's SHA-512 integrity, then copies them into private staging. It preloads the exact local tarballs with `npm cache add --offline --ignore-scripts` and runs fixed `npm ci --offline --ignore-scripts --no-audit --no-fund --engine-strict=false`; package scripts are not invoked. The explicit engine setting preserves npm's default advisory handling regardless of ambient config. The process runs as uid/gid 65534 inside Bubblewrap with no network namespace, a 1 GiB memory limit, 50% CPU, 64 tasks, and a 240-second systemd runtime. Aggregate expanded tarball size is capped at 1 GiB; the installed tree is capped at 1.5 GiB and 50,000 files. Only safe relative in-tree npm bin symlinks are accepted; the tree is hashed, made root-owned and read-only, and its manifest is published after completion. The authenticated API persists the verified receipt and the desktop offers install/remove actions. Live WSL acceptance covers offline module loading, a generated `.bin` symlink, lifecycle marker absence, repeat install, integrity status, and exact removal. A live registry acceptance fetches `is-odd@3.0.1` and its `is-number@6.0.0` dependency through the Windows AppContainer broker, installs both offline, runs the root package from the selected procedure sandbox, and removes the exact tree: [report](../../.acceptance/npm-live-registry-transitive-20261114/report.json). A scoped package and nested transitive dependency install from exact locked tarballs and load through a procedure-bound command: [report](../../.acceptance/npm-transitive-graph-20261114/report.json). A further Ubuntu 24.04 acceptance loads a required peer and root optional dependency, and confirms an absent peer marked optional is allowed: [report](../../.acceptance/npm-optional-peer-graph-20261114b/report.json). Platform-filter checks confirm npm 9.2 skips optional `win32` and `arm64` packages on Ubuntu WSL x64 while retaining compatible packages: [OS report](../../.acceptance/npm-platform-optional-20261114/report.json), [CPU report](../../.acceptance/npm-platform-cpu-optional-20261114/report.json). A duplicate-version graph confirms npm 9.2 resolves root `2.0.0` and the scoped plugin's nested `1.0.0` copy independently: [report](../../.acceptance/npm-duplicate-versions-retry-20261114/report.json). A required package locked to `win32` fails under Linux without publishing an environment, while optional incompatible packages are skipped: [report](../../.acceptance/npm-required-platform-20261114/report.json). These are deterministic fixtures with npm 9.2.0 on one WSL distribution; broad npm package compatibility remains unverified. Procedure execution binding is verified in step 5.
5. **Implemented and locally verified:** a run may select only an approved installed lock for the exact imported procedure version and authorized WSL distribution. A unique installed match is recorded automatically; multiple matches require an explicit digest choice. The immutable selection event stores the environment digest, distribution, and tree hash. The command journal binds this proof and the procedure ID/version to the command intent. WSL rechecks the installed tree under a shared lease, mounts only its node_modules read-only for that procedure version, and adds its .bin directory to the sandbox PATH. The lease remains held through manager cleanup, so removal is refused until the command finishes. Live WSL acceptance imports a fixture from the selected procedure script, observes removal refusal during an active command, verifies cleanup, then removes the exact environment: [report](../../.acceptance/npm-node-environment-6b7f7990aeaf4a5fabbe17763ede3bac/report.json). A second acceptance runs two distinct procedure IDs concurrently with the same package name/version but different verified archive bytes; each imports its own module value, active removal is refused for both, and exact cleanup preserves the other environment: [report](../../.acceptance/npm-cross-procedure-isolation-20261114/report.json). These are deterministic fixtures on one WSL distribution and do not establish model-mediated procedure execution or broad npm compatibility.
6. **Partially verified lifecycle/recovery:** exact-digest removal can recover an invalid manifest or corrupt tree while holding the manager lock and exclusive digest lease; it verifies the exact root-owned directory, stops the exact transient installer unit, and confirms it is inactive before deletion. Unit regressions cover corrupt-manifest removal, adjacent-environment preservation, and refusal while a command holds the lease. Live WSL acceptance kills a real offline npm installer service with SIGKILL, verifies no partial receipt remains, and retries the same digest: [process-kill report](../../.acceptance/npm-process-kill-recovery-20261114/report.json). It installs procedure version 2 under a separate digest, runs the retained version 1 successfully, removes v2, confirms v1 remains intact, then removes v1: [rollback/runtime/isolation report](../../.acceptance/npm-version-rollback-20261114/report.json). The same acceptance confirms the module link resolves only through the selected procedure path, no project-root `node_modules` appears, and hashes of the WSL Node/npm trees and global-module location are unchanged across install, execution, and removal. These checks cover one WSL distribution and deterministic fixtures. Source and frozen Windows AppContainer workers reject correctly integrity-hashed tarballs with traversal, absolute/backslash paths, symbolic and hard links, FIFO entries, duplicate members, missing package metadata, truncated or checksum-invalid gzip streams, per-file size over 64 MiB, more than 20,000 members, and aggregate expansion above 256 MiB: [30-case worker matrix](../../.acceptance/npm-archive-bounds-20261114/report.xml). This does not establish broad npm archive or package compatibility. The model-mediated imported procedure run remains deferred until the end per the user's preference.

npm's root operating-system, CPU, and libc metadata and [devEngines](https://docs.npmjs.com/cli/v11/configuring-npm/package-json#devengines) are documented in [package.json](https://docs.npmjs.com/cli/v11/configuring-npm/package-json#os) (`process.platform`, `process.arch`, and Linux libc family); npm's platform matching and libc detection are implemented in [npm-install-checks](https://github.com/npm/npm-install-checks/blob/main/lib/index.js), [current-env](https://github.com/npm/npm-install-checks/blob/main/lib/current-env.js), and [dev-engines](https://github.com/npm/npm-install-checks/blob/main/lib/dev-engines.js). Package-lock and `npm ci` semantics are documented at [package-lock.json](https://docs.npmjs.com/files/package-lock.json) and [npm ci](https://docs.npmjs.com/cli/commands/npm-ci/). In particular, `npm ci` requires a lockfile and checks that the lock and manifest agree; `ignore-scripts` prevents install-time lifecycle scripts but does not prohibit deliberately invoking a script command. X.A.A. must keep installation commands fixed and execute no package script as part of setup.
