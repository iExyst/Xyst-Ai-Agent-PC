# Owned prompt-counting service

The authenticated API provides `POST /providers/lm-studio/token-count`. Supply an already-loaded model instance identifier, text/tool `messages` and optional OpenAI-shaped `tools`. The response contains model ID, SDK-rendered prompt-token count, loaded context length and SDK version. CLI: `uv run xaa tokens "Say hello." --model MODEL_INSTANCE_ID`. Counting never loads/downloads a model, requests prediction, executes a tool, or writes a run journal.

The provider shares its inference/lifecycle lock with counting. Queue wait is deducted from the default 20-second worker allowance. A timed-out or cancelled waiter does not launch a child. A count request is limited to one MiB, 256 text/tool messages, eight tool calls per message and 32 tool definitions. Unsupported roles, incomplete tool results, malformed/non-object arguments and non-loopback/proxied server addresses fail explicitly. This first adapter supports plain HTTP loopback LM Studio only.

The engine sends a fixed JSON request to its own `--tokenizer-worker` entry point. The worker formats through the SDK's public Chat methods, matches an exact loaded instance from inventory, applies tool definitions, tokenizes and reads loaded context. It returns at most 32 KiB of strict count/error metadata. It does not import the API service or open SQLite. Text prompts, rendered templates and token arrays are not returned or logged. The worker returns exception class names only; SDK exception text is not exposed. The parent preserves the type name as machine-readable diagnostic metadata while its user-facing exact-context error remains generic.

Provider credentials come from the existing engine configuration/Windows vault and travel through the worker's input pipe. They are absent from arguments and environment during process handoff; the SDK then authenticates to the selected loopback server. `XAA_API_TOKEN`, `LM_STUDIO_API_TOKEN` and `LM_API_TOKEN` are removed from the child environment; an explicit SDK credential or empty token prevents ambient SDK fallback. Proxy variables are removed and NO_PROXY is forced to * so this loopback-only adapter connects directly. Public requests cannot override credentials or server address. Filesystem workers now also scrub LM_API_TOKEN. No OS-vault value was fabricated or server authentication setting changed during verification.

Source tests use the real SDK against a local synthetic WebSocket server, including its greeting and deliberately stalled authentication. They verify explicit credential propagation, ignored ambient credentials, cancellation/timeout closure, input/output boundaries and safe errors. Initial in-process AsyncClient cancellation left the authentication connection open; that design was replaced with process ownership. Cancellation, timeout, invalid response and oversize output terminate and join the exact owned process tree. The shared termination helper preserves the existing filesystem-worker behavior. This is lifecycle control for trusted SDK RPC, not an execution sandbox for generated code.

## Dependency choice

Runtime and lockfile pin `lmstudio==1.6.0b1`, a prerelease. Stable 1.5.0 did not expose the documented API-token argument; 1.6.0b1 does and matched the four prompt fixtures previously measured on 1.5.0. PyInstaller collects the SDK and metadata. The prerelease choice, actual authenticated-LM-Studio acceptance and clean-machine/license review remain release considerations; synthetic authentication tests do not establish a real server credential integration claim. [Official SDK authentication reference](https://lmstudio.ai/docs/python/getting-started/authentication), checked 2026-11-04.

## Scope

The standalone service returns the SDK-formatted count and does not itself reserve a budget. Exact-context inference integrates counting, durable reservation and HTTP admission under the provider lock when enabled by `XAA_EXACT_CONTEXT=1` or per run with `pre_inference_token_reservations`. The per-run setting requires a configured `max_total_tokens` and is available through the authenticated run API, CLI, and desktop limits form. It applies to coordinator diagnostics, parent requests and specialist requests. The request fails closed on count or reservation errors. Matching HTTP usage is verified for four text/tool/history fixtures on the installed 9B model, Qwen3 0.6B and Qwen2.5 0.5B. The SDK context-manager health probe caused cross-process timeouts on the two smaller models; the worker now skips that redundant one-second HTTP probe and uses its first SDK RPC for connection validation. See [tokenizer evaluation](../evaluations/tokenizer-parity.md). Other models/templates/media and broader history cases remain unevaluated. Exact-context mode remains opt-in; ordinary inference uses conservative context preflight. No SDK agent loop is introduced; tool execution remains in the existing coordinator. Reservation is a pre-request budget admission mechanism, not a guarantee against server-side misreporting or token use outside X.A.A.'s coordinated provider.

Durable token holds (2026-11-04): automatic exact-context mode now calls the coordinator's admission callback while retaining the provider lock, after successful context checking and before HTTP. `tokens.reserved` stores only inference ID, optional task ID, counted prompt tokens, output cap and their sum. Diagnostics, parent responses and specialists participate. Specialist attempts/replies now carry unique inference IDs; legacy journal rows remain readable. The reservation transaction checks the live parent lease, specialist lease when applicable, known reported usage, outstanding holds, the parent threshold and optional specialist allowance. Equality fits. Duplicate, answered or missing inference IDs reject. Counted prompt plus output must fit before prediction, even when existing reported usage alone is below the threshold.

A hold remains outstanding until a durable matching model/incomplete/diagnostic reply contains measured usage. Cancellation, crash or missing usage does not refund it. A measured reply implicitly substitutes actual usage for its hold, so the existing response transaction is the release boundary; there is no intervening release-before-save window. Historical unknown calls fail closed. This mode is opt-in and uses SDK-rendered counts; arbitrary models/templates, server misreporting, independently changing LM Studio clients and broad hard-budget parity are still unproven. Default mode retains the earlier reported-token threshold semantics. Task scheduling with shared thresholds remains serialized.
