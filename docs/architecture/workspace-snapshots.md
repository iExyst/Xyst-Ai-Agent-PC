# Bounded workspace snapshots for restricted execution

`engine/xaa/runtime/workspace_snapshot.py` captures a project into immutable byte records with per-file and manifest SHA-256 digests. The format/decoder/materializer uses the Python standard library; only Windows-side capture imports the existing verified-file-handle reader. The same decoder therefore runs in the existing Linux manager without installing application Python packages there.

Capture enumerates a selected canonical workspace, refuses included symlinks/junctions/reparse points and special files, then verifies each actual opened file handle remains inside the workspace before consuming bytes. File size/mtime/ctime must remain stable around the read. This is a set of individually captured file versions, not an atomic point-in-time transaction across an independently edited project. The manifest identifies the exact captured bytes; future executor results must retain that digest rather than claim they validate a later project revision.

Limits fail the complete capture instead of silently truncating: 256 files, 256 directories, 2 MiB per file, 8 MiB total contents, 12 MiB wire envelope, 16 path components, bounded UTF-8 names, 2048 enumeration entries and a five-second cooperative enumeration deadline. Worker ownership/timeouts still need integration around potentially blocking filesystem operations. `.git`, `.venv`, `node_modules` and `__pycache__` directories are omitted and recorded explicitly; validation cannot assume omitted dependencies are present in the sandbox.

The codec rejects traversal/absolute/drive/UNC-style paths, backslashes/Windows device names, empty/dot path components, case collisions, duplicate JSON keys, invalid base64, incorrect byte counts, unknown fields, unsupported formats and content/manifest digest mismatches. Every parent directory must be declared; files cannot also be directories or parents. Binary bytes and Unicode names survive unchanged. Hard-linked regular source files become separate copied files, with no original inode reference.

Materialization accepts only a decoded immutable snapshot and creates a new private directory exclusively. It refuses an existing destination, creates only declared directories/regular files and never merges changes into the original project. It must run in an application-owned private staging area; arbitrary model-selected host destinations are not part of the contract. The Linux diagnostic decodes before creating staging and guards cleanup on every exit. Original workspace mounts, directory links, named pipes, devices and host credentials are not transported. Project-file read authorization remains necessary; snapshotting is not a classifier that removes secrets from otherwise authorized project files.

## Actual transport acceptance

`uv run python scripts/wsl_sandbox_probe.py --distribution Ubuntu-24.04` creates a small Windows fixture, captures it through verified handles, and streams only the bounded snapshot JSON to the selected Linux host script using structured arguments. Trusted manager/codec source paths are selected by the diagnostic, not by model arguments. The manager executes no project content outside the restricted process. A traversal-mutated envelope is rejected before any staging creation. The valid snapshot materializes into private Linux staging and is bound read-only into Bubblewrap; its scratch mount remains separate and bounded.

Evidence `.acceptance/245ae1df-bee4-4d80-8d3c-3c18d76acc7b/` and `../releases/evidence/wsl-snapshot-transfer.json` confirms matching snapshot digests, Unicode/binary reads from inside the sandbox, all earlier isolation/resource probes, inactive owned units and unchanged original Windows project bytes. Fifteen unit cases exercise Windows junction refusal, redirected opened handles, bounds, path injection, digest tampering, case conflicts, empty directories, deterministic identity and independent staging edits. A cleanup refactor initially indented diagnostic command text incorrectly in `.acceptance/39672b8a-6855-4d9e-8f1f-f0beaafbc0d5/`; the fixture-text dedent was corrected and the complete actual transfer reran successfully. The failed run remains evidence, not a pass.

This is transport groundwork for Phase 3. Product execution remains disabled pending durable command intents, selected distro/profile readiness, bounded output artifacts, cancellation/crash reconciliation, production syscall policy and real model/native defect-patch-validation acceptance. Writable sandbox copies and reviewed hash-checked result integration remain open. No broad execution parity or completed project-validation gate is claimed.
