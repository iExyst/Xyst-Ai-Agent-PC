# Managed browser reads

Updated 2026-11-08. This is an initial Phase 7 browser slice, not general browser automation or Hermes parity.

## Run flow

The desktop has a separate per-run **Allow managed browser reads** grant. At least one exact DNS hostname must also be approved. The API saves both with the run, and the coordinator advertises `browser_run` only when both are present. Browser output is labeled `untrusted_web_content`.

`browser_run` accepts an HTTPS URL, up to five exact accessible link names, an optional screenshot flag, and an opt-in form-inspection flag. It can navigate, follow links, read bounded visible page text, inspect up to 20 visible forms and 100 controls for tag/type/name/label/required state and up to 20 choice labels per select, and capture a viewport PNG. It never reads control values, form actions, or cookies. It has no form fill, submit, button click, download, or persistent-profile operation. Form metadata and page text are untrusted. A screenshot is stored as a managed `image/png` artifact and is previewable in the desktop.

The coordinator starts a short-lived Python worker with engine and provider bearer tokens removed from its environment. The worker launches the installed Microsoft Edge channel with a new nonpersistent context, blocks service workers, downloads, permissions, and QUIC, closes pages opened beyond the primary page, and closes both context and browser at completion. Cancellation or timeout ends the owned process tree. Worker input and output are capped at 1 MiB; visible text at 20,000 characters; screenshots at 512 KiB; the proxy limits each run to 32 tunnels and 2 MiB transferred data.

All browser requests must use HTTPS to an exact approved host and GET/HEAD. A local CONNECT proxy checks every hostname, resolves DNS, rejects the request if any answer is not globally routable unicast (including private, reserved, multicast, or unspecified addresses), and opens the tunnel directly to one of the validated IP addresses. Chromium's loopback proxy bypass is removed so local and metadata destinations cannot avoid the proxy. Playwright request routing independently checks URLs/methods, including redirects and page requests.

## Limits

This is not an OS-level isolated browser. Edge runs under the current Windows account with its normal browser sandbox and processes untrusted public pages. GET requests can still trigger state changes on poorly designed sites; the run permission is therefore an explicit grant, and callers should avoid URLs/links that perform writes. Browser automation does not inherit the user's Edge cookies or profile. Edge must be installed. Sites that require login, non-GET application requests, or another host are unsupported by this slice. Form inspection exposes page supplied labels as untrusted data; it does not grant authority to interact with controls.

## Verification

- `uv run pytest -q tests/unit/test_browser.py tests/unit/test_api.py tests/unit/test_web_fetch.py tests/unit/test_web_search.py`
- `uv run python scripts/browser_smoke.py` verifies live Edge navigation and PNG artifact registration against `example.com`.
- `uv run python scripts/browser_popup_smoke.py` launches installed Microsoft Edge, opens a local `about:blank` popup, and verifies the managed callback closes it while preserving the primary page.
- `uv run python scripts/browser_redirect_smoke.py` verifies an approved cross-host redirect and that an unapproved redirect fails without returning destination content. It uses the [Postman Echo API](https://learning.postman.com/docs/reference/developer-resources/echo-api) redirect endpoint and a fixture page from HTTPBin.
- `uv run python scripts/build_engine.py` builds the frozen Windows engine including Playwright resources.
- `uv run python scripts/frozen_browser_diagnostic.py` launches the packaged worker against `example.com` and verifies page text and PNG output.

Live navigation evidence is saved in [`browser-live.json`](../releases/evidence/browser-live.json), packaged-worker evidence in [`browser-frozen-live.json`](../releases/evidence/browser-frozen-live.json), and form-inspection evidence in [`browser-forms-live.json`](../releases/evidence/browser-forms-live.json). The form smoke inspected HTTPBin's live public form, journaled one form and 12 controls, and confirmed values were absent. Resolver unit tests cover private, loopback, link-local, carrier-grade NAT, documentation, multicast, unspecified and IPv6 unique-local addresses; live proxy bypass tests for internal destinations remain open. Focused tests exercise the shared request guard against approved and off-host document/subresource URLs and POST requests. Local real-Edge acceptance verifies an approved Postman Echo redirect to an approved HTTPBin fixture and blocks an off-host redirect before returning destination content (`.acceptance/browser-redirect-edge-cc525856cc174f8cb70b5ad780a90378/report.json`). A follow-up navigates to HTTPBin with only `httpbin.org` approved, confirms an off-host stylesheet request is blocked, and records a bounded count by resource type (`.acceptance/browser-redirect-edge-71071a14efd04d02a13ce96623726fd9/report.json`); hosted repetition is pending. This does not cover broad resource types, nested frames or long redirect chains. Additional pages opened by the main page are closed, with deterministic callback coverage and a local real-Edge `about:blank` popup smoke (`scripts/browser_popup_smoke.py`). Hosted Windows run [42526498899](https://github.com/iExyst/Xyst-Ai-Agent-PC/actions/runs/42526498899) passed this smoke on Microsoft Edge 156 and uploaded its report; this does not establish public-site popup behavior. A Windows integration test cancels the managed worker wrapper and confirms its child process stops; real Edge navigation cancellation and timeout acceptance remain open. Broader live sites and installer acceptance of the browser worker also remain open.
