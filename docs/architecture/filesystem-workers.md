# Coordinator filesystem workers

The coordinator's read, write, create, replace, patch, directory-list and recursive-search calls run in short-lived owned processes. Specialist read/list calls use the same path, with internal results excluded from parent conversation replay. Candidate file verification, final run-review checks and specialist evidence-review checks also use owned internal read workers. Pending write/create intents are reconciled through an internal-only worker operation before coordinator continuation. A fixed operation enum and strict request schema select application code; this interface does not accept arbitrary commands or generated Python. SQLite leases and durable tool intents/results still enforce ownership inside the worker. Specialist assignment deadlines cancel and join their worker through the existing outer task timeout.

The source launcher uses `python -m xaa.runtime.tool_worker`; the frozen launcher uses the bundled engine's `--tool-worker` entry point before importing API startup or requesting credentials. Requests/results use private stdin/stdout pipes, each capped at 1 MiB. The engine API token and provider API-token environment variable are removed. Errors return class names without argument contents or credential values. Output is read incrementally with a hard cap. Stderr is not exposed to model context.

The execution/pipe exchange deadline is at most ten seconds, clamped to the remaining run budget; process startup and cleanup add overhead. Expired budgets and oversized requests are rejected before spawning. Timeout/cancellation stops and joins the owned process. On Windows, `taskkill /PID <owned PID> /T /F` stops the PyInstaller bootloader and application descendants; this is fixed application lifecycle code. An actual frozen-worker diagnostic observes the descendant tree, cancels a worker blocked on SQLite, then confirms all observed PIDs exited and the fixture was unchanged.

Worker failures/deadlines put the coordinator into `blocked` for inspection. Cancellation follows the existing pause/cancel ownership rules. A timed-out write may already have changed a destination: its journal remains authoritative, and existing exact-byte reconciliation must run before any repetition. The parent never treats worker termination as proof that an action did not happen.

Workspace file reads retry recognized transient canonical-path resolution and open/read errors at most twice (three total attempts), with 50 ms then 100 ms backoff. Resolution retries apply to the selected workspace root and requested file/directory before an intent is persisted; each retry is lease-fenced and journaled with its stage, attempt and delay. Every open/read attempt rechecks the lease, opens a fresh handle and verifies its actual destination before consuming bytes. Windows uses `CreateFileW` to preserve sharing-violation codes that Python's regular CRT opener can collapse into generic `EACCES`. Plain access denial, missing paths and containment failures are not retried. Writes and result persistence are outside the retry loop.

On explicit resume, or after obtaining a new review lease, interrupted version-1 built-in read/list/search intents can be closed transactionally as failed with `effect: read_only` and code `interrupted_read`. No filesystem call is replayed and no old contents are inferred. A public failure result is attached only to a matching saved parent tool proposal; helper/unmatched results stay internal. New read/list intent events preserve the internal flag, and legacy unmatched helpers also stay out of replay. The model must propose a new read if it still needs the data. Unknown tools, unknown versions, writes and anomalous execution-marked intents are left unresolved. The current lease is checked in the same transaction, fencing late output from the interrupted owner.

All files in one candidate/final-review check share a ten-second execution budget, additionally clamped to remaining run time for coordinator checks. Final review retains its 30-second lease and repeats checks against fresh bytes; worker errors/timeouts return a conflict without committing acceptance, while cancellation releases the review lease. A completed run is still committed only through the guarded state/revision transaction. Process startup/cleanup can add overhead to the check budget.

Specialist evidence review shares one ten-second budget across selected evidence reads. It retains the parent review lease and rechecks evidence hashes before the guarded task decision. Worker errors/deadlines return conflicts; cancellation releases ownership without completing the task or unlocking dependents. Reconciliation runs only when unresolved write/create intents exist. Its worker accepts no arguments and requires the internal flag; it confirms exact effects without creating another write, while missing/unchanged/conflicting destinations remain unresolved.

Scope remains partial: the synchronous task-verification library helper remains available for direct callers, metadata queries after canonical path resolution and filesystem calls outside the version-1 read/list/search preflight remain without transient retry, and unknown or anomalous intents still require inspection. A proposal interrupted before its tool intent was persisted also remains blocked. Search retains its existing cooperative three-second scan budget inside the worker; the outer worker deadline can stop a stalled filesystem call. This process boundary provides responsiveness and lifecycle control, not a security sandbox for generated code.

Restricted command/project-validation execution remains unavailable on this machine: the 2026-11-03 check found neither `docker` nor `podman` on PATH. Windows OpenSSH is installed, but no isolated remote execution destination is configured. Generated-command tools remain disabled until a restricted backend is implemented and verified.

Directory enumeration also retries recognized transient read errors up to three attempts with 50/100 ms backoff. Each attempt checks the live lease and opens a fresh directory handle, verifying its resolved workspace boundary before enumeration. Partial enumeration is discarded on error. Windows errors preserve `winerror`, including sharing violations. Permission denial and missing directories are not retried; exhausted intents remain available to read recovery. Metadata/path-resolution failures before the intent are not covered by these retries.

Process termination/join is shared with the new tokenizer worker in `runtime/processes.py`; filesystem worker protocol and ownership checks remain unchanged. SDK ambient LM_API_TOKEN is also scrubbed from filesystem-worker environments. Frozen cancellation regression `.acceptance/524637d5-07b1-40b0-adf0-34453369aebb/` verifies bootloader/application children exit, fixture bytes remain unchanged and no intent is left unresolved.

Unicode protocol correction (2026-11-04): worker responses now use explicit UTF-8 bytes on stdout.buffer, matching binary JSON input and parent parsing. Locale-dependent sys.stdout.write could fail after a Unicode read was already journaled as completed. Forced CP1252 source and actual frozen read/list checks pass; `.acceptance/ed92aa2b-f5c8-4957-b4bb-9e685977e6a8/` verifies Unicode filename/content, unchanged bytes/mtime and no unresolved intents. Ownership, permission and cancellation behavior remain enforced by the existing worker protocol.
