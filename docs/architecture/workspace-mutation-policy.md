# Workspace mutation policy

Workspace permission authorizes project edits. It does not authorize rewriting the running application or its private execution records. The specification requires application changes to follow the ordinary development/release process.

All WorkspaceExecutor creation and edit paths, including replacements, patches and write reconciliation, pass the actual engine database location to the handle layer. Existing-file checks use the final opened handle destination while exclusive Windows sharing is held, before reading or writing. Creation checks use the final verified, pinned parent handle and requested filename before NtCreateFile creates a file. Existing containment, no-reparse creation, hash preconditions and hard-link refusal remain in force.

Reserved destinations include the engine import tree, source desktop application and source sidecar entry point, active Python environment/base runtime, frozen executable directory and extraction root, the actual SQLite database plus WAL/SHM/rollback journals, and managed artifacts/backups. Directory aliases are resolved when matching protected roots. Execution-manager state and staging under both supported WSL UNC server names are reserved, as are their native Linux paths. Ordinary project files beside an engine database remain editable; selecting a broad folder cannot grant mutation authority over the reserved children.

The policy is derived by application code from runtime paths and the database, rather than from model arguments, a procedure, or project text. External development tools can still change the application through the normal repository/release process. Low-level handle helpers accept an optional database for internal callers; every model-accessible WorkspaceExecutor mutation supplies it.

Verification on Windows: tests/unit/test_mutation_policy.py exercises actual executor creation/edit refusal with unchanged fixtures and resolved journal entries, the SQLite filename family, opened Python-runtime edit refusal, source import/desktop/entrypoint paths, frozen executable/extraction path selection, real artifact-directory junction aliases, and both WSL UNC names. Frozen paths are unit simulations; a newly packaged desktop has not yet been used for this policy acceptance. Existing hard-link, containment, junction, collision and worker tests remain applicable. Creation is currently Windows-only and portable edit locks do not claim Windows sharing guarantees.

This completes a source file-tool mutation boundary, not the entire restricted-command product gate. The command transport/controller, remaining wall budget, cross-engine admission policy, packaged manager resources, explicit UI permissions, startup/reboot recovery and real model/native command validation remain open. Command output is still untrusted and command writes remain private snapshot changes.
