# Specialist filesystem authority

Specialist workers carry the saved task ID and opaque worker token in the private worker protocol. Model tool arguments cannot select that scope, a root directory, parent ownership or an operating mode. Both scope fields must be present together. Ordinary scoped filesystem requests permit only internal read/list operations; dedicated private workspace operations additionally require the task's saved workspace.write permission.

A scoped RunStore validates the current parent lease and exact running task/token/expiry, workspace.read permission and saved task-to-parent workspace binding. The same validation applies at filesystem intent and result transactions, not just in the coordinator before launching a child. Its get_run view uses Observe mode and omits any parent command grant. Parent operations without task scope retain their normal run permissions.

Specialist model and tool-result events are published only in a transaction that rechecks parent and task authority. Expiry/revocation after a read therefore cannot publish a completed result or candidate evidence under stale task ownership. An interrupted read can remain unresolved until existing recovery examines it; scope loss never implies successful execution.

Write-enabled specialists now receive isolated snapshot-backed working trees. An immutable registered artifact captures the original project; completed task-owned journal entries overlay private edits. No private edit writes the original project. These are logical trees, not host directories or Git worktrees. Read-only tasks retain their original scoped reads. Snapshot creation and private read/list/write/create run in owned workers and recheck the exact saved task authority. Ordinary scoped host writes remain forbidden, and private command execution additionally requires both the parent's explicit saved local-user command grant and the task's separate workspace.command permission.

Snapshots allow at most 4 MiB of source content per task and 32 MiB of snapshot artifacts per run, subject to existing file/path limits. Each task may change at most 16 net file paths totaling 1 MiB; proposed deletions count by the original file size, and restoring a removed path reduces the net change set. Complete file reads/writes are limited to 64 KiB. Artifact size/hash and completed overlay journal hashes are verified before review. Duplicate call IDs or idempotency keys are refused. Private writes commit atomically with their journal result, so process failure cannot leave an unjournaled host edit.

The review panel shows complete proposed diffs, including deletion markers, checks current project bytes, and requires explicit authorization before integration. Conflicts require an explicit current/proposed choice with the observed current hash. The engine rechecks project bytes and applies approved content through frozen filesystem workers using compare-and-swap or exclusive creation. Approved deletions acquire exclusive Windows handle access, reject links and hard-link aliases, rehash the exact current bytes, durably record execution, then mark that same opened file for deletion. Saved authorization binds the task, exact bytes or deletion, local review lease and unique action ID. Partial integrations remain journaled. An unfinished integration intent blocks further writes until reconciliation; a completed write is recognized by its proposed hash and is not replayed. Deletion recovery only observes missing/unchanged/conflicting state and never retries deletion. A known pre-effect failure permits a fresh explicit review with a new action ID.

This implements bounded user-reviewed create/write/delete integration. Automatic merging, autonomous reviewers, task restart/adoption and private artifact retention controls remain open. Keeping current content is an explicit user decision, not proof that the rejected proposal's criteria were satisfied. File deletion integration is Windows-only and fails closed elsewhere.

Private validation commands require workspace.read, workspace.write and workspace.command in the saved task scope. The parent must have an explicit local-user WSL grant; no grant is inferred from a model proposal. Each command freezes the current private artifact/journal tree through an owned snapshot worker. No task can choose a host root or another task's copy. Task token/expiry/permission/binding and parent ownership are checked at reservation, capture, snapshot acceptance, launch and result commitment. The existing restricted WSL profile, aggregate command admission, deadlines, cancellation cleanup and no-replay recovery remain in force. Command-generated changes are discarded; edits continue through private file tools.

Command results and immutable stdout/stderr artifacts belong to the task and stay out of parent model history. The review panel shows actual argv, exit/termination, output excerpts and inspectable saved output. Evidence includes the exact executed snapshot hash; later private edits make it stale. Accepting a command-enabled task requires explicit selection of successful validation for the current private tree. Output artifacts are rehashed before presentation/acceptance. Exit zero supplies evidence for the reviewer; it does not prove arbitrary acceptance criteria. Conflict choices may alter the integrated result, which still needs independent project validation. Recovery may preserve matching completed output after scope loss, but cannot relaunch the command or publish a new specialist answer under stale ownership.

The distribution must already exist and satisfy the unchanged sandbox profile. Acceptance scope and retained failures are in `../releases/evidence/task-commands.json`.

For multiline source, workspace_write_lines accepts exact lines and an explicit final_newline flag. The trusted adapter joins them with LF and delegates to the same private CAS write boundary; it never decodes backslash escapes or guesses the intended text. The original structured model call and the canonical executed write remain in the task history/journal. This avoids an extra escaping layer while retaining the existing full-text write tool for exact content. Regression checks preserve literal backslash-n strings and final-newline choices.

The specialist prompt now includes its saved budgets and the remaining model-request allowance, including an explicit last-request reminder. Tools and permission boundaries remain unchanged; all actual requests still consume the existing shared/task budgets. A candidate can report incomplete work and always awaits independent review. This guidance does not add an extra response beyond the saved iteration limit.
