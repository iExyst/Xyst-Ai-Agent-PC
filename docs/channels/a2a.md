# A2A peer access

X.A.A. accepts bounded text tasks with an optional inline image through an authenticated A2A JSON-RPC listener. Tasks use the same persistent coordinator as the desktop app, run in Observe mode, and receive no workspace or tool grants.

## Enable a listener

1. Open **Tools & integrations → Messaging channels → Agent-to-agent (A2A)**.
2. Create an A2A peer credential and copy the displayed secret to the connecting peer. X.A.A. stores the credential in Windows Credential Manager and shows the secret only once.
3. Select a PEM TLS certificate and matching private key. The certificate must cover the machine name or IP address that peers will use. Keep the private-key file protected by your Windows account permissions.
4. Keep **Allow TLS connections from other devices on this network** unchecked for local-only use. To accept peers on a LAN, check it and enable the listener. Network binding is refused without a valid certificate and private key. The Agent Card URL uses HTTPS, and connecting peers must trust the certificate.
5. If Windows Firewall blocks inbound connections, add a rule for the selected port. Give peers the desktop's machine name or IP address; `0.0.0.0` is the bind address, not a client destination.

The network listener exposes only `GET /.well-known/agent-card.json` and `POST /a2a`. The broader owner API remains bound to loopback. The peer credential can submit, stream, query, and cancel A2A tasks; it cannot access owner settings or grant tools/workspace permissions. TLS protects credentials and task contents in transit, but a publicly trusted certificate and a narrow firewall rule are still needed for peers outside the local machine.

## Supported protocol slice

The listener accepts canonical A2A v1 JSON-RPC names `SendMessage`, `SendStreamingMessage`, `GetTask`, and `CancelTask`, plus the older slash-style aliases. Requests are limited to 4 MiB plus envelope allowance and text prompts to 10,000 characters. A request may contain one inline `raw` PNG, JPEG, GIF, or WebP image part; the selected model must advertise vision. Message IDs are deduplicated across retries, and task state remains queryable after the engine restarts. `GetTask` returns bounded user/agent history and a stable text artifact when a response is available. When the selected history includes the inbound image message, it reconstructs the normalized image as a v1 `raw` part from the digest-verified managed artifact; image bytes are not persisted in the A2A event journal. A candidate awaiting X.A.A. owner review reports `TASK_STATE_INPUT_REQUIRED`; the stream sends the candidate artifact and closes so the peer can poll for the owner's decision. `historyLength` is validated and capped at 100 entries. The official `a2a-sdk` Python client acceptance exercises discovery, streaming, polling, image submission and image history against a local deterministic provider; it does not contact an externally hosted agent or use a live model.

Inbound text tasks can include one inline PNG, JPEG, GIF, or WebP image as an A2A v1 `raw` part with `mediaType`. The image is size-bounded, checked against the selected model's advertised vision support, normalized through the normal image-input path, and stored as a managed run artifact. Remote file URLs are rejected and never fetched. The run event stores only artifact metadata; task history reconstructs the normalized image bytes from managed storage when that user message is included. Outbound image/file parts, document/audio attachments, push notifications, broader A2A methods, automatic replies, and live interoperability with an external agent are not implemented or verified yet. This is a partial channel implementation, not a claim of full A2A or Hermes parity.

## Send a task to an authorized peer

Under **Authorized outbound peers**, enter the peer's HTTPS Agent Card URL and bearer token. X.A.A. stores the token in Windows Credential Manager and never shows it again. A peer must be explicitly added by the owner; only a button press sends a task, and the model cannot select or change the destination. You can replace or clear a peer token without deleting its task history.

X.A.A. discovers only an A2A 1.0 JSON-RPC endpoint on the configured HTTPS origin and sends the explicit `A2A-Version: 1.0` header. It verifies the certificate, disables redirects and ambient proxies, and bounds connection time and response size. Outbound tasks use the same local Observe-mode authority boundary; a remote peer's text is untrusted and cannot grant local tools or workspace access. Each send stores an idempotency key before dispatch. Repeating the same key and text returns the saved delivery record; changing text with that key is rejected. If the network outcome is unclear or the app stops during a send, the task is marked **unknown** and is never automatically resent. Inspect the remote peer before starting a new task. Use **Refresh remote task** to query a known remote task ID. The owner can request **Cancel remote task** from the saved task list; the cancellation result is journaled separately. An unclear or interrupted cancellation is marked **unknown**, and only another explicit owner action retries it.

The local acceptance uses two separate X.A.A. instances and an independent server built with the official A2A Python SDK, all with a test-trusted HTTPS certificate and deterministic providers. It verifies discovery, streaming, authenticated outbound submission, polling, artifact retrieval, remote cancellation, idempotent replay, and owner-API isolation. Unit coverage verifies ambiguous-send and ambiguous-cancel recovery without automatic replay. No external peer service or live model is used.
