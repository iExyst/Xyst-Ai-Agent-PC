# Telegram channel setup and operation

X.A.A. supports paired private Telegram text, photo, document, and Windows PCM WAV messages through the Bot API. Photo messages are downloaded only for an authorized private account and only when the selected LM Studio model advertises vision capability. X.A.A. selects the largest Telegram photo variant, caps the download at 3 MiB, rejects redirects and unsafe file paths, fully decodes JPEG/PNG content, and rejects rasters over 1,600 pixels per side or 2.5 megapixels before storing a managed run artifact. One PDF, DOCX, XLSX, UTF-8 TXT, Markdown, or CSV document up to 4 MiB is downloaded only for an authorized private account with a selected model. Its MIME type and content are validated; the source and bounded extracted text are retained as untrusted run artifacts with a sanitized filename. A PCM WAV document up to 4 MiB is validated and transcribed with the installed Windows System.Speech recognizer; the source audio and untrusted transcript are retained as run artifacts. Duplicate update IDs are checked before media is fetched or transcribed. Unsupported, invalid, or oversized documents are ignored. Native OGG voice notes and other audio formats are not supported. Group and unpaired messages are never downloaded. Telegram Bot API requests use HTTPS and the official `getMe`, `getUpdates`, `getFile`, `sendMessage`, and file-download endpoints. The client ignores environment proxy settings, disables redirects, and caps API responses at 2 MiB. See the [Telegram Bot API documentation](https://core.telegram.org/bots/api).

## Configure the bot

1. Create a bot with Telegram's official BotFather and copy its HTTP API token.
2. In X.A.A., open **Messaging channels → Telegram**.
3. Paste the token and choose **Verify and save bot token**. X.A.A. verifies the bot identity, then stores the token in Windows Credential Manager. The token is never returned by the API or placed in run context.
4. Choose **Generate one-time pairing code**. In a private Telegram chat with the displayed bot, send the exact `/pair CODE` command before the five-minute expiry.
5. Refresh channel status and confirm the linked-user count. **Revoke all linked users** is a two-step control that disables every pairing for the currently configured bot; saved sessions and runs remain available. Clearing the bot token only stops polling and does not erase run history.

Only the private account that proves possession of the local one-time code is linked. Group chats and unpaired users do not create runs. A user message creates an Observe-mode run with the currently selected LM Studio model and no workspace grant. It enters the same persisted coordinator and supervisor used by the desktop.

When a run completes, its saved public answer is sent to the paired private chat. Failed, blocked, and cancelled runs send a generic notice directing the user to review the saved run in the desktop app. Delivery status and Telegram message ID are recorded locally.

If a paired user sends a photo while vision is unavailable or the image fails validation, X.A.A. creates no run and sends a short explanation through the durable reply outbox. A successfully sent notice is also saved in the paired session without associating it with a run. Ambiguous send outcomes use the same owner-reviewed reconciliation flow as run replies.

## Scheduled result messages

The Automations screen lists currently linked private Telegram accounts as optional destinations. Selecting one explicitly authorizes one message for each scheduled occurrence to that account. The destination is bound to the bot account and Telegram user ID; the server rejects a destination that is no longer linked. Revoking links also cancels pending scheduled messages for those users. A send already in progress cannot be recalled. Optional quiet hours use `HH:MM-HH:MM` in the schedule's IANA timezone, including overnight ranges such as `22:00-07:00`. Scheduled work still runs at its configured time; only its result message waits until the quiet window ends. Repeated local times follow the timezone's normal conversion, and the message becomes eligible at the next poll after the configured end time.

Scheduled messages use a durable per-occurrence outbox. The execution history records `sent`, `failed`, `unknown`, `revoked`, or `retrying`, with total send attempts and the UTC retry time exposed in Automations. The adapter saves send intent before calling Telegram and does not retry an ambiguous outcome after a timeout or restart. The owner can inspect the selected Telegram user and explicitly mark an uncertain occurrence delivered or retry it after checking the chat; this choice is stored in a durable reconciliation audit. Manual retry still respects the three-attempt cap and current account authorization. An explicit Telegram 429 rejection can be retried using its validated `retry_after` value, capped at five minutes and three total send attempts. Retry times persist across restart and remain subject to quiet hours and current account authorization. Other definitive rejections fail immediately. Runs without a selected destination do not create a delivery record or send a message.

## Delivery and recovery behavior

Telegram update IDs are stored with the input run in one SQLite transaction before the next polling offset advances. Repeated updates therefore resolve to the same saved event and do not create another run. The adapter uses one offset per bot. It drops an offset after six days without an update because Telegram may randomize the next update ID after a week without updates; Telegram retains incoming updates for at most 24 hours.

Before sending a reply, X.A.A. changes its durable delivery state from pending to sending. A successful response stores the Telegram message ID and sent state. A definitive API rejection becomes failed. A network timeout, invalid response, or server error becomes unknown and is never automatically retried, since Telegram may have accepted a message before the client lost the response. The desktop lists each uncertain reply with its Telegram user, run, and update time. The owner must inspect the private chat before choosing to mark it delivered or retry the existing reply. The API only accepts reconciliation while the same bot account is configured, requires an explicit destination-checked confirmation, changes only a still-unknown delivery, and records each resolution durably. A retry returns the delivery to the normal pending outbox; a delivered resolution records it as sent. A mistaken retry can still create a duplicate, so the UI warns before confirmation.

This adapter handles text, bounded PNG/JPEG photos, and one bounded supported document, including Windows PCM WAV, in paired private chats. Scanned PDFs without extractable text, native OGG voice notes, other media, group scopes, retries for ordinary (non-scheduled) replies, commands beyond pairing, cross-channel identity links and other Telegram account modes remain unsupported. Bot status is scoped to the bot account verified from its token. A real configured bot and authorized test chat are required to verify external delivery; fixture tests do not establish live Telegram interoperability.
